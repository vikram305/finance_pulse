## Canonical Term Registry

| Term | Canonical Definition | Source | Notes |
|------|---------------------|--------|-------|
| **Pulse** | The product's working title. An offline-first financial simulation utility. | PRD §1 | — |
| **Sandbox** | The core simulation environment. Available on web and mobile. | PRD §3, §4.2 | — |
| **Scenario** | Named container of FinancialEvents. UUID + name + ordered FinancialEvent ID list. Max 2 active in V1. | TDD §2.1, ADR-008 | Never "Plan" or "Timeline" |
| **FinancialEvent** | UUID-keyed block: name, polarity, startMonth, endMonth, amount, isBaseline. Atomic unit of the Sandbox. | TDD §2.1 | Never "transaction" or "entry" |
| **Strawman** | Auto-generated FinancialEvent blocks seeded from 50/30/20 rule. `isBaseline = false`. | ADR-003, PRD §4.1 | — |
| **Baseline** | FinancialEvent with `isBaseline = true`. User-confirmed, permanent expense. | TDD §2.1 | — |
| **ProjectionNode** | Engine output for one month in one Scenario: monthIndex, startingBalance, netCashFlow, endingBalance, activeEventIds. | TDD §2.1 | — |
| **ProjectionEngine** | Pure function `List<ProjectionNode> calculate(Scenario, List<FinancialShock>)`. Stateless, O(N×M), synchronous, 12–36 months. | TDD §2.2, ADR-010 | — |
| **Panic Room** | Mobile-only stress-test module. Applies FinancialShocks across all Scenarios simultaneously. | PRD §4.3 | Never on web |
| **FinancialShock** | App-level (not Scenario-scoped) stress event. UUID + label + list of FinancialEvent deltas. | TDD §2.1 | — |
| **Projected Resilience** | Per-Scenario score 0–100 = `min(runwayMonths / 12, 1.0) × 100`. UI label is ALWAYS "Projected Resilience". | ADR-009, TDD §2.1 | NEVER "Resilience Score" in UI |
| **ResilienceScore** | Internal entity name (code). The UI label is "Projected Resilience". | TDD §2.1 | Code name ≠ UI label |
| **Runway** | Months until ending balance reaches zero. Raw input to Projected Resilience formula. | ADR-009 | — |
| **`.pulse` file** | PBKDF2-encrypted portable file containing serialized BLoC state. | ADR-004, TDD §4.2 | Must be cross-platform compatible |
| **Master PIN** | User-defined PIN set once at mobile onboarding. PBKDF2 input for database encryption and mobile `.pulse` files. Never stored in plaintext. | ADR-004 | Mobile only |
| **Ephemeral PIN** | One-time PIN entered at web export. Discarded immediately. | ADR-004 | Web only |
| **PBKDF2** | KDF: min 100k iterations, SHA-256. Library: `cryptography ^2.9.0` + `cryptography_flutter ^2.3.4`. | TDD §4.2 | — |
| **SandboxBloc** | BLoC managing `Map<ScenarioId, Scenario>` + ProjectionEngine calls. Provided at MaterialApp root. | TDD §2.2 | — |
| **PanicRoomBloc** | Mobile-only BLoC. Manages FinancialShock activation. Registered with `!kIsWeb` guard. | ADR-011 | — |
| **DatabaseService** | Singleton. Manages Drift database lifecycle. Branches on `kIsWeb` for encrypted mobile storage (SQLCipher) vs. unencrypted IndexedDB on web (Drift WASM). | TDD §4.1, ADR-018 | Drift |
| **Web Playground** | Session-scoped Flutter Web (WASM) build. State in IndexedDB (volatile). Excludes Panic Room, Projected Resilience, import, biometric, database encryption. | PRD §3, ADR-007 | Intentional lock-in mechanic |
| **kIsWeb** | Flutter compile-time constant. Canonical feature gate for all mobile-only code. Tree-shaken by compiler. | ADR-011 | No runtime abstraction |
| **TimelineChart** | `RepaintBoundary`-wrapped custom Bezier painter. Receives `Map<ScenarioId, List<ProjectionNode>>`. One trajectory per Scenario. | TDD §3.1, ADR-005 | — |
| **10-Second Hook** | Onboarding goal: cold open → populated Scenario trajectory in <10s, 2 inputs only. | PRD §4.1, ADR-003 | — |
| **A/B Scenario Forking** | Creating a second named Scenario for simultaneous comparison. Available on web and mobile. | PRD §4.2, ADR-008 | — |
| **Shock chip** | Quick-toggle UI element in Panic Room that activates/deactivates a FinancialShock. | PRD §4.3 | — |
| **Projection Window** | User-adjustable horizon: 12/24/36 months (default 12). Hard cap 36. | ADR-010 | — |
| **Biometric gate** | Native-only foreground re-auth via `local_auth`. Absent from web. | TDD §4.3 | — |
| **Presentation shielding** | OS-level screen obscuring on backgrounding. Native only. | TDD §4.3 | — |
| **getpulse.com** | SEO-optimized HTML/CSS marketing landing page. Not Flutter WASM. | PRD §3, ADR-007 | — |

## Resolved Decisions (Do Not Re-Grill)

| Decision | Resolution | ADR |
|----------|-----------|-----|
| Data ingestion | Manual 2-input start + Strawman correction. No SMS, no PDF. | ADR-001, 002, 003 |
| Business model | 100% free, open source, no ads | ADR-006 |
| Web/mobile split | `kIsWeb` compile-time constant | ADR-007, ADR-011 |
| Scenario cap | Hard cap of 2 in V1 (BLoC guard only) | ADR-008 |
| Resilience formula | `min(runwayMonths / 12, 1.0) × 100`, 12-month ceiling | ADR-009 |
| Projection window | 12–36 months adjustable, default 12, hard cap 36 | ADR-010 |
| Rendering | Custom Bezier CustomPainter in RepaintBoundary | ADR-005 |
| PIN/encryption | PBKDF2 via `cryptography ^2.9.0` | ADR-004 |
| Database choice | Drift with `sqlcipher_flutter_libs` (mobile) and Drift WASM (web) | ADR-018 (supersedes ADR-014) |
| Web storage | Drift WASM via Web Worker, unencrypted IndexedDB | ADR-007, ADR-018 |
